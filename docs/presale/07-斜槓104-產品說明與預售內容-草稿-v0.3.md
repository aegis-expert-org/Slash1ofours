## 3. 產品概述

斜槓104 / Slash104 是由其獨立法人機構（完整法定名稱 [暫定]／[待確認]）規劃中的企業級數位分身授權平台（`slash1ofours.com`），延伸自斜槓一二三，但知識主體從個人專家改為公司、法人、團隊與專案組。成員把負責範疇的資料餵入公司指定的地端 FHE AI NAS，經審核者核可後才併入正式分身；分身與其授權收益歸公司所有，成員離職或調組不會帶走知識明文。

授權分為兩層：對內依 OWNER、ADMIN、REVIEWER、CONTRIBUTOR、CONSUMER 角色與部門配置，人員異動即撤權；對外由公司簽發 B2B 授權合約與 USB 綁定憑證，預設禁止再授權。資料可標記為「自有」「第三方授權」或「僅限內部」，標記為僅限內部的知識不會出現在對外標售的分身中。平台不訓練模型、不收存明文知識包，只留下不含問答內容的審計收據。

## 4. 核心特性與功能（可驗證者優先）

以下摘自 README，實作完成度均為 [待確認]。

1. **多層組織**：公司帳號與個人帳號分離；下設處、部門、團隊與專案組。
2. **五階 RBAC**：OWNER（所有權、定價、移轉與下架）、ADMIN（成員調配、NAS 綁定、簽發對內外金鑰）、REVIEWER（審核知識包）、CONTRIBUTOR（餵入資料）、CONSUMER（持鑰提問）。
3. **人員異動連動**：離職、調組、撤權即標記失效並同步至 NAS 側，新請求阻斷（README 目標：秒級／< 3 秒 [待確認]）；已併入知識留存公司。
4. **審核閘門**：未審核片段只留暫存區，不被 RAG 或微調索引。
5. **智財標籤隔離**：`IP_PROPRIETARY`／`IP_LICENSED`／`IP_INTERNAL_ONLY`；僅限內部資料無法被對外分身檢索。
6. **依業務線建立多個專精分身**（README 例：製程安全、研發配方、售後客服），各自有 Skills 邊界。
7. **雙層授權與多金鑰**：對內短效憑證（README：5–15 分鐘 [待確認]）；對外限制次數、期限、領域，`REAUTHORIZE=FALSE` 預設；同一分身可多家夥伴並行，額度與紀錄獨立。
8. **硬體在位**：USB 插入並通過 FIDO2 驗證才解密；拔除即清除 Client 記憶體。
9. **企業分身卡片與防洩漏試問**：不公開成員名冊與原稿；未付款只提供合成示範或混淆密文樣本；交付物為授權物件與金鑰啟用憑證，不交付原始資料庫。
10. **審計收據與零明文仲裁**：日誌只記企業 ID、分身 ID、Grant Hash、時間、額度、節點簽名；管理層只看用量與成功率。

## 6. 差異化定位

**跨法人相鄰產品（斜槓一二三、斜槓104 及 AEGIS 各自獨立）**

- **vs. 斜槓一二三（`slash1to3.com`）**：**兩者不可混為同一產品。**

| 構面 | 斜槓一二三 | 斜槓104 |
| :--- | :--- | :--- |
| 主體 | 個人專家 | 公司、法人、團隊、專案組 |

| 知識餵入 | 本人直接匯入 | 成員餵入，需 Reviewer 核可 |
| 資產所有權 | 專家個人 | 公司實體（成員離職不影響） |
| 授權架構 | 個人直接授權外部買方 | 雙層：對內治理＋對外標售 |
| 卡片展示 | 個人分身，顯示履約紀錄 | 企業能力卡，不公開成員名單 |

- **vs. FHE AI NAS**：NAS 是企業知識與模型所在的執行節點；斜槓104 是組織治理與授權交易中樞，不存知識、不跑模型。
- **vs. HEShell**：HEShell 是本機殼層與密文路由，不處理組織權限與授權交易。

**跨法人**

- **vs. 永恆記憶 EternalMemory（Wonderland Center）**：數位回聲為已故人物的受控數位仿生；斜槓104 為企業在世團隊的能力授權，兩者不可並列。
- **vs. VeilProof 隱證（AllView）**：VeilProof 是商務推演與訓練；斜槓104 是知識授權，無功能重疊。

**相對於一般企業知識庫或 AI 助理**：差異在「審核才併入」「僅限內部標記與對外分身隔離」「雙層授權」，以及原始知識不離開企業設備、平台不經手問答明文。

## 7. 預售說詞（草稿，可直接改用）

> 以下文案只陳述 README 中已寫明的設計範圍，不包含價格、席位、交期、法規合規或效能保證。

### 短文案（知識留在公司）

資深工程師離職，帶走的常常是最難補回來的判斷力。斜槓104 讓團隊成員把負責範疇的知識餵入公司自己的地端 NAS，經審核者核可後才併入公司的數位分身；分身與授權收益歸公司所有，人員異動時權限立即撤銷，知識留在公司，也不會以明文被帶走。

### 短文案（對外授權）

想讓供應鏈夥伴或客戶查詢你們團隊的專業判斷，又不能交出製程文件？斜槓104 讓公司以 B2B 合約授權外部夥伴向特定分身提問，可限制次數、期限、併發與領域；標記為「僅限內部」的資料，對外分身查不到。對方買到的是提問權利，不是你們的資料庫。

### 賣點句

- 分身歸公司：成員離職不帶走知識明文。
- 審核才併入：未經 Reviewer 核可的資料不被索引、不對外回答。
- 內外分流：「僅限內部」資料與對外分身邏輯隔離。
- 雙層授權：對內依角色治理，對外依合約標售，預設禁止再授權。
- 一個分身、多家夥伴：額度與審計紀錄各自獨立。
- 管理層看用量，不看內容：不調閱員工或買方問答明文。

## 核心定位

延伸自斜槓一二三（`slash1to3.com`），知識主體由個人專家改為**公司、法人、團隊與專案組**。平台**不訓練模型、不收存明文知識包**；將多位成員在企業地端 FHE AI NAS 受保護區貢獻、經審核併入的組織知識，轉化為「歸屬公司、雙層授權（對內／對外）、可計量、可稽核」之企業數位分身權利交易與驗證中樞。

## 原則

1. **分身與智財歸屬公司**：成員離職或調組不帶走知識明文。
2. **審核閘門與智財標籤隔離**：未經審核的資料不得被正式分身引用；`IP_INTERNAL_ONLY` 資料只能進內部分身。
3. **買授權，不交知識本體**：原始文件、製程配方與模型權重不離開地端 NAS。
4. **雙層授權**：對內依角色與團隊配置、離職即時撤銷；對外由公司簽發 B2B 授權合約與 USB 綁定憑證，預設禁止再授權。
5. **硬體在位驗證**：USB（FIDO2 / CTAP2 / Secure Element）不在位即無法解出答案；拔除即清除記憶體明文。
6. **匿名使用但不可否認**：平台與外部節點不經手問答明文；每次調用留下審計收據。

## 功能

### 組織與權限
- 公司帳號與個人帳號分離（個人可兼屬多公司；與個人知識之區隔 [待確認]），下設處、部門、團隊、專案組。
- RBAC：`OWNER`（所有權、定價、移轉、下架）｜`ADMIN`（成員、NAS 綁定、簽發金鑰）｜`REVIEWER`（審核知識包）｜`CONTRIBUTOR`（餵入資料）｜`CONSUMER`（持鑰提問）。（原稿另列 Member，與 CONSUMER 是否相同 [待確認]）
- 人員異動：離職、調組、撤權即同步至 NAS 側並阻斷新請求（目標：< 3 秒 [待確認]）。

### 智財與審核
- 標籤：`IP_PROPRIETARY`（對內外皆可）｜`IP_LICENSED`（依第三方授權條款）｜`IP_INTERNAL_ONLY`（嚴禁外授權，對外分身無法檢索）。
- Reviewer Gate：未審核片段僅留暫存區，不被 RAG 或微調索引。
- 依業務線建立多個專精分身，各有 Skills 邊界。

### 授權與金鑰
- 對內：依職級與部門批量簽發短命憑證（原稿：5–15 分鐘 [待確認]）。
- 對外：限制次數、期限、領域；`REAUTHORIZE=FALSE` 預設。
- 多金鑰並行：多家外部夥伴額度與紀錄獨立。
- USB 插入並通過 FIDO2 驗證才解密；拔除即 Wipe。

### 市場
- 企業分身卡：發行企業、團隊領域、Skills、能答範圍、不能答邊界、USB 支援；不公開成員名冊與原始文件。
- 防洩漏試問：未付款僅合成示範或混淆密文樣本。
- 交付物：授權物件（Grant Object）與硬體金鑰啟用憑證；不交付原始資料庫。

### 審計
- 提問端直連企業 NAS，平台不中繼、不落地問答記錄。
- 日誌僅記：企業 ID、分身 ID、Grant Hash、時間戳、額度消耗、節點簽名。
- 管理層僅可檢視用量與成功率，不得調閱員工或買方問答明文。
- 爭議僅比對授權範圍、期限、額度紀錄與收據。
